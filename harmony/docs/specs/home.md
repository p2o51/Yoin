# v1 port spec: Home (root page, Subsonic account)

> Generated 2026-11-13 by reading the Android app (read-only agents). Android refs are relative to app/src/main/java/com/gpo/yoin. The "Corrections" section at the end overrides anything above it.

## Overview

WHAT THE USER SEES, TOP TO BOTTOM (phone, Compact). A full-bleed page on the shell's vertical gradient (surfaceContainer -> background -> surfaceContainerLow). One scrolling list: (1) header = small greeting line over the big "Home" title on the left, account avatar button on the right (48dp touch box, 32dp avatar; with no account a Settings gear); the Memories pill/bubble sits between them and is deferred, so the middle stays an empty weight(1) gap. (2) Activities bento: section title "Activities", then a tinted hero card (album or playlist you last played/opened, with year/songs/minutes footnote), a row of small square card + wide card, and a pill strip; each card's tint is lerped from its own cover palette. If there is no history at all the whole section is one empty card "No activity yet" (no section title). (3) Jump Back In: 3-column x 4-row shelf of 12 covers (albums on a Bun backdrop, songs on a Circle, playlists on a Ghostish), mixed round-robin, title + artist under each; a stable random pool re-rolled at most every 6 h. (4) Recently Added: one horizontal full-bleed shelf whose first item is a 2x2 track grid (52dp covers) followed by album cards (82dp Bun cover) - items starred in the last 30 days. (Rediscover sits here in the Android order but is deferred.) (5) Recently Played: shelf of album cards from the server's play history, minus albums already in the Activities bento. (6) Your Playlists: shelf of playlist cards (82dp Ghostish cover + "N songs"). Sections with nothing to show are skipped silently; the list ends with 108dp + nav inset of bottom clearance for the floating bar. Taps: album card -> album detail (PushPage); playlist card -> playlist detail; artist card -> artist detail; any song card/tile -> plays that single song at once (queue of 1, no navigation). Long-press and long-press-to-edit-home are deferred. Status bar: content sinks under two waves of page colour (the tide line) that appear over the first 40dp of scroll, and text fades out just below the line. First appearance of the feed plays a 3-beat staged reveal (hero 0 ms, Jump Back In +90 ms, the rest +170 ms) once per process. There is no pull-to-refresh and no banner for offline/failed blocks: a block whose read fails keeps what it had, an empty read hides it; a full Error page (message + Retry + Settings) only appears if the load itself throws before anything is up. Load order is layered: local tier first (activity log + persisted Jump Back In pools) then network blocks splice into the same screen as they land.

## v1 must

### 1. 1. Page frame, scroll, background, spacing

Single CustomScrollView over the gradient page background: Brush.verticalGradient([scheme.surfaceContainer, scheme.background, scheme.surfaceContainerLow]) filling the Home page (same as Library; the Flutter shell already crossfades both pages and keeps them alive so scroll position survives). Feed frame class 'Capped' for Compact: side margins 16dp, content width = min(containerWidth, 720) - 32 (i.e. <=688, centred on wider containers; formula: start = 16 + max(0, (min(W,840)-720)/2), content = min(W - start - 16, 688), end = remainder). Vertical gap between list items 18dp (10dp on a landscape handset = height<480). List top padding 0 (the header supplies status-bar inset + 12dp). List bottom padding = 108dp (LibraryTokens.bottomGroupPadding) + system nav-bar inset (landscape handset: 16dp + inset). Items in order: header, then one item per visible section in layout order. Horizontal shelves (Recently Added, Recently Played, Your Playlists) are full-bleed: the shelf ignores the page margins (spans the container) and uses contentPadding = the frame's start/end margins, so resting items align with the page margin and scroll to the real screen edge (no mid-page truncation - owner rule, memory 'No mid-page truncation'). No pull-to-refresh, no overscroll action in v1 (Android's pull-down-at-top opens Memories; Memories is deferred, so plain scroll physics). Scroll position stays when switching Home<->Library and when a detail page is pushed and popped. Cover/palette work is gated: no palette extraction while the list is scrolling and not until 350 ms after the first scroll-idle (HomeBackdropPaletteWarmupDelayMillis).

**Motion:** The whole feed enters on first Content: alpha 0->1 on the Expressive default EFFECTS spring (damping 1, stiffness 1600) and translationY 16dp->0 on the Expressive default SPATIAL spring (0.8, 380); both only start once Content exists (flag hasPlayedInitialContentEntrance flips one frame after first Content, then stays true for the process). While Loading the feed alpha target is 0. Margins/frame are a lerp driven by the live container width; frame-class changes ease on a spatial spring (deferred beyond Compact).

### 3. 3. UI states: Loading, Content, Error

Sealed state Loading / Content / Error, switched exhaustively. Loading: nothing is drawn for the first 180 ms (HomeLoadingIndicatorDelayMillis), then the app's loading indicator (YoinLoadingIndicator, an M3 Expressive LoadingIndicator, centred) springs in; it leaves on its own exit when Content/Error arrives. Content: the feed. Error (only when the very first load throws with nothing up - practically a local storage failure; network block failures never produce it): centred Column - message in bodyLarge colour error (text = exception message, else 'Failed to load home content'), 8dp gap, Row spacing 12: TextButton 'Retry' (re-runs the load) and TextButton 'Settings' (opens Settings). A feed that goes back to Loading (account switch) leaves on the same springs it came in on (fade + settle back 16dp) before the indicator takes over; a switch to another account starts at the top, the same account's feed keeps its scroll. On first launch with NO account configured Android never reaches Home (onboarding); in Flutter show the header plus the Activities empty card and let the header button lead to Settings (Library uses a 'connect' prompt - do the same only if the shell can reach Home without an account).

**Motion:** Indicator: AnimatedVisibility with Expressive-role fadeIn (effects spring) + scaleIn from 0.6 (spatial spring); exit mirrors. Feed leaving/entering: see item 1. Loading must not report 'motion pressure' during an account switch (only during the cold start; capped at 3 s) - in Flutter just don't tie animations to it.

### 5. 5. Activities data (what feeds the bento)

Source is the LOCAL activity log, not the server. Event = {id, entityType ALBUM|ARTIST|PLAYLIST|SONG, actionType PLAYED|VISITED, entityId (raw id), profileId, provider, title, subtitle, coverArtId (CoverRef storage key: URL or raw cover id), songId?, albumId?, artistId?, timestamp ms}. Read newest 320 rows (limit 40 x 8) for the active profile+provider, collapse to the newest per key 'actionType:entityType:entityId:provider', take 40 (HOME_ACTIVITY_LIMIT). Bento selection: dedupe again by 'entityType:entityId' (SONG events keyed by songId) keeping the first (newest, whatever the action), then DROP all SONG events (single plays never earn a card). Entries (phone takes the first 8, ActivityBentoPhoneXlEntries): hero = first ALBUM-or-PLAYLIST entry among the first 6 (artists never hero); every other entry in recency order is a 'supporting' candidate. Seated supporting cards at the default L preset on phone: 3 (small, wide, strip); preset S=0, M=2, L=3, XL=5. Entry fields: stableId='activity:<id>:<entityType>:<entityId>:<actionType>', title=event.title, subtitle=event.subtitle or (ARTIST -> 'Artist' else 'Recently active'), typeLabel (Album/Artist/Playlist/Track), timeAgo (item 19), coverArtUrl = resolve(coverArtId) at size 320 else (Subsonic only) entityId for ALBUM, else albumId, else null; target = Album('subsonic:'+rawId) | Artist | Playlist | Song(track rebuilt from the event). Entity ids may be stored raw or 'provider:raw' (legacy) - strip the provider prefix before use. Live: the log is observed; each change is debounced 1000 ms and the Activities block (and its hero footnote, and Recently Played's dedupe) re-derive - a play shows up in Home within ~1 s without a reload. Hero footnote: only for an ALBUM hero, re-resolved only when the hero entity changes: source.library.getAlbum(heroId) (detail cache first) -> year, songCount if >0, minutes = durationSec/60 if durationSec>60, version tag; any failure drops the line (never shows an error); a PLAYLIST hero has no footnote.

**Motion:** Hero footnote line expands in (Expressive spatial spring, expand from top) with a fade (effects spring) when it arrives after the card, and shrinks/fades out on a hero change while still showing the last footnote.

### 7. 7. Jump Back In data (pools, rotation, grid cards)

Cards are built from three persisted candidate pools per profile+provider: albums, songs, playlists. Rotation: pools older than 6 h (GRID_POOLS_TTL_MS) or missing are re-fetched IN THE BACKGROUND while the old pools (any age) are painted first: getAlbumList(random, size 24) -> distinct by id -> shuffle -> take 14; getRandomSongs(16) (only if Capability randomSongs, else starred tracks shuffled) -> distinct -> take 10; getPlaylists() (the one shared read, also feeds Your Playlists) -> distinct -> shuffle -> stable-sort artless playlists (coverArt==null) last -> take 10; persist atomically; if every read failed or all came back empty, keep the old pools untouched. Pool write failure never costs the shelf. The shelf is deterministic from pools: albumPool/trackPool/playlistPool (each stable-sorted so covers with art come before artless ones, hidden-by-user cards removed - hide is deferred), primary = round-robin interleave(albums[0..3), tracks[0..2), playlists[0..3)) = album,track,playlist,album,track,playlist,album,playlist (8), extras = round-robin interleave(albums[3..], tracks[2..], playlists[3..]); result = (primary+extras) stable-sorted artless-last, take 28 (GRID_MAX_COMPACTS). Phone shows the first 12 (3 columns x 4 rows; trimToPhoneShelf with cells=12; with no signal cards all 12 are covers). Card model: stableId 'grid-album:<id>' | 'grid-song:<id>' | 'grid-playlist:<id>', entityType ALBUM->Bun, SONG->Circle, PLAYLIST->Ghostish, title (album name / track title / playlist name), subtitle (album artist / track artist / playlist owner unless it is the placeholder 'Playlist'; blank is allowed), version (albums only), coverArtUrl = resolveCoverUrl(ref, size 480) falling back (Subsonic) to the album id as coverArt id, target AlbumDetail(id) | PlaylistDetail(id) | PlaySong(track). Signal ('1x2') cards (rating/review/note, memory) do not exist in v1: every card is a compact cover. Fewer than 12 candidates simply give a shorter last row (rows keep column width via trailing spacers).

**Motion:** None for the data; the grid re-packs (a pool rotation landing while the page is open) by crossfading on the Standard effects spring with the section height easing on the Expressive spatial spring (springHeight) - never a hard cut. v1 may simply keep the painted shelf until next launch (Android also re-rolls only on rotation).

### 13. 13. Status-bar tide line and text fade (seam)

Home's top seam = 'FadeText' + tide. (a) Tide: a full-screen overlay above the list draws two filled waves in the page colour (colour = scheme.surfaceContainer, the gradient's TOP stop; the same fill over bare page is invisible) from above the screen top down to the wave line, so content sinks UNDER the water line. Geometry: reveal r = clamp(scrolledPx / 40dp, 0, 1) (scrolledPx = list scroll offset, 0 at rest => no tide at rest); rest line = statusBarHeight + 2dp (TideRest); base = rest*r - 8dp*(1-r) (hidden 8dp above the screen until scrolled). Front wave: y = base + A*(sin(2pi*(x/72dp + phase)) + 0.18*sin(2pi*(x/36dp - 1.7*phase + 0.3))), A = 2.4dp + 3.2dp*stretch; back wave: base + 6dp, amplitude 1.1*A, wavelength 116dp, phase 0.37 - 0.7*phase, drawn FIRST at 55% alpha. phase = (travelPx + lagPx)/88dp where travelPx is scroll travelled and lagPx a lagging afterglow follower; sample every 3dp across width +/-20dp. stretch = smoothstep((scrollSpeed_dp_per_s - 150)/1300) (speed follower is first-order; at rest stretch 0, wave still; reduced motion: A fixed 2.4dp, phase 0). Followers snap to rest below 2 dp/s. (b) Text fade: every text block that has the seam modifier (header lines, card titles/subtitles/labels, section titles) fades as it rises into the seam line y = statusBarTop + 2dp (+ tideTextSeamPx(reveal) when the tide is the viewport's own): band = max(lerp(10dp, 26dp, stretch), 0.75 * fontSize) * r; alpha(x) over the band, x = 0 at the line to 1 at band end: 0 for x <= 0.05, else t=(x-.05)/.95, alpha = 1-(1-t)^2. Implement as a per-element ShaderMask/DstIn gradient only for elements near the top (cheap: skip elements far from the seam). (c) Graphics (covers, tinted cards) pass under the tide untouched in v1 (no dots at the top for FadeText). The bottom bar's halftone field is deferred.

**Motion:** Continuous: driven by scroll offset and scroll speed, not by a spring clock; the speed follower decays with SeamFlowSettleStiffness 90 (critically damped, ~0.5 s). Keep the tide in one CustomPainter fed by a ValueListenable (no widget rebuild per frame).

### 15. 15. Load orchestration, caching and refresh policy

One trigger loads Home: the active scope (profile id + provider) plus explicit refresh requests (Retry, active account's credentials edited). On scope change cancel the running load (generation counter), keep what is up if the next scope is a hand-over, show Loading otherwise. Layered publish: (1) local tier = activity log read + persisted JBI pools of any age (+ hero footnote resolving right behind it) goes up first as ONE Content; (2) network blocks launched in parallel at load start - Recently Added (getStarred), Recently Played (getAlbumList recent), Your Playlists (getPlaylists, also shared with the pool rotation), pool rotation if due - each splices into the already-published Content as it lands and owns only its own fields (so splices may land in any order); a splice that changes nothing publishes nothing. Failure rule per block: failed read -> keep the previous list of that block (count it, no UI); successful empty read -> clear it. Until the local tier is in, blocks collect in a draft that the local tier publishes with them. A sourceless load (credentials unreadable) publishes once, empty. In-process cache: last Content per scope key ('provider|profileId'); a Home re-created in the same process paints from it at once (no Loading) and still refreshes. Persisted cold-start snapshot of the whole feed (covers stored as CoverRef storage keys, never URLs, because Subsonic URLs carry credentials) is deferred; the persisted JBI pools are the only disk cache in v1. No periodic refresh, no refresh on app resume, no pull-to-refresh; Activities alone is live (activity-log observer, debounce 1 s, hero footnote re-resolved only on hero change). The scope also reloads when the active source object is rebuilt for the same profile (credentials edited).

**Motion:** Section height/placement changes caused by a block landing animate (see item 4); the feed itself is not re-entered.

## Data calls
- Local: ActivityLog.watchRecent(profile, provider, limit 320 rows) -> collapse newest per 'action:entityType:entityId:provider' -> take 40 -> Activities hero/supporting entries; debounced 1000 ms; live (no polling); also re-derives Recently Played's dedupe and, on hero change, the hero footnote.
- source.library.getAlbum(heroAlbumId) -> hero footnote (year, songCount>0, durationSec>60 -> minutes, version); read through the detail cache (memory LRU + disk) so it is usually local; only when the hero entity changes; failure = no footnote.
- Persisted pools read: KV 'home.gridPools.<profileId>' (albums, tracks, playlists, cachedAt). Fresh (<6 h) -> use; stale/missing -> paint stale (any age) then rotate in background.
- Pool rotation: source.library.getAlbumList(AlbumListType.random, size 24) + source.library.getRandomSongs(size 16) (Capability.randomSongs) + the shared getPlaylists() -> distinct/shuffle/sort(artless last)/take 14/10/10 -> persist -> rebuild shelf. All-failed or all-empty -> keep old pools.
- source.library.getStarred() once per load -> Recently Added tracks (<=16) and albums (<=20), filter star timestamp within 30 days, newest first. Needs the star timestamp, not Child.created.
- source.library.getAlbumList(AlbumListType.recent, size 20) -> Recently Played, minus albums in the bento (20 first activities' ALBUM ids).
- source.library.getPlaylists() once per load (shared by Your Playlists, take 20 in server order, and the pool rotation).
- source.resolveCoverUrl(ref, size: 480) for Jump Back In covers; size 320 for activity covers, shelf albums, track tiles, playlist cards; Subsonic fallback ref = album raw id as cover id when a card has no cover.
- Playback: PlaybackController.playTracks([track]) for song taps. Navigation: DetailRoutes.openAlbum/openPlaylist/openArtist.
- Failure/refresh: each network block independent, failure keeps previous, empty clears; reload only on scope change (profile or provider), credentials edit (source object rebuilt) or Retry; no pull/resume/timer refresh. Per-scope in-memory Content cache ('provider|profileId') so a recreated Home paints instantly.

## Gaps in the HarmonyOS framework
- Persistence: Harmony storage is only KeyValueStore (Preferences) + SecretStore; Android uses Room for activity_events, home_grid_pool_cache, home_layout and the feed snapshot. - Cover palette extraction (CoverSeedExtractor + backdropColorsFrom/tone functions, 16-colour Palette quantiser with Android's default swatch filters, 96-entry LRU, retry policy, scroll gate): absent in Flutter and shared with Now Playing; needs an isolate-based decode+quantise service returning {base, accent}.

## Risks
- Recently Added will be wrong or empty if Home reads Flutter's current addedAt (Subsonic `created` = file added to the server): Android uses the star timestamp (`starred`). Fix the model before building the shelf.
- Activities stays empty (only 'No activity yet') until playback and the album/artist detail pages write ActivityLog events; Recently Played (server `recent` list) also stays empty unless the app scrobbles plays (MusicPlayback.submitPlay / reportNowPlaying; Android scrobbles when a play passes its rule, Capability.PLAY_REPORTING). These are cross-area dependencies in the playback/detail specs - confirm them before QA or Home will look broken on a clean install.
- No offline/error banner by design: a failed server leaves a sparse Home (header + 'No activity yet') with no retry affordance; Android has the same behaviour but gets instant content from its disk snapshot, which is deferred here. Consider (owner call) a refresh on resume/connectivity change if first-launch-offline QA looks bad.
- Palette extraction is the main CPU cost: ~25 distinct covers on screen at once; run decode+quantise off the UI thread, cache by URL, and respect the scroll gate or fling will drop frames (Android's own perf notes: wave/marquee/palette cost, docs/perf).
- Marquee titles inside intrinsic-height layouts crash on Android; in Flutter give the hero/wide cards fixed heights (124/118dp x textScale) rather than IntrinsicHeight, and avoid IntrinsicWidth in the MetaLine.
- Persisted pools in a single KV blob: concurrent writes from two code paths (rotation and a profile switch) can clobber; key per profile and serialise writes. A KV blob growing with ActivityLog (400 events) must stay small (store storage keys, not credentialed URLs).
- Subsonic cover URLs carry credentials: never persist resolved URLs; persist CoverRef storage keys only (URL-shaped refs are stored as URL, source-relative ones as the raw cover id) and re-resolve through the active source.
- getAlbumList2 random can return duplicates and Navidrome playlists may lack covers: always distinct by id and sort artless items last (already in the rule), else the shelf shows grey holes.
- Backdrop shape approximations (proto.js SVG) differ slightly from MaterialShapes Bun/Ghostish; owner reviews shapes closely (memory: shape semantic tokens, no cover borders). Get a visual sign-off before polishing the morph.
- Language: English noon = afternoon string is intentional; Chinese has four distinct greetings. Chinese fonts have no ROND axis (falls back to the system font) - do not try to synthesise rounded Chinese.
- Home is the first screen with many springs at once (feed entrance, staged reveal, tide, press, palette): budget frame time on the Mate 70 Air (120 Hz); Android already freezes covered shells and pauses loops - Flutter should pause the tide listener and reveal tickers when Home is covered by Now Playing or a pushed page.

## Corrections (from a second reader — these win)
Overall the spec is accurate. Strings, plurals, section order, numbers for the header, bento, Jump Back In, Recently Added, shelves, tide and reveal all match the Android code. I found these corrections and additions.

**Wrong or misleading**

1. **Jump Back In pool rotation (item 7 and its `motion` line).**
   - Rotation triggers only when the TTL-bounded pool read succeeds and returns nothing (`HomeViewModel.loadLocalTier`). Stale pools are painted first, and a failed pool read means no rotation that load.
   - The "keep the old pools" rule is `any read failed AND no read returned anything`. If all three reads succeed but come back empty, an empty snapshot with a fresh `cachedAt` is persisted and replaces the old pools. It is not kept.
   - "v1 may simply keep the painted shelf until next launch" is wrong for a first launch or a new account. With no persisted pools the shelf is empty, so Jump Back In would be missing until the next launch. A rotation result must splice into the live page (`spliceRotatedPools`). Only the crossfade and `springHeight` animation may be skipped, and the section simply appears.
2. **Recently Played re-derive (item 5, "Live").**
   - Only the load path (`spliceActivities`) re-derives Recently Played with `notShownIn`. The live `observeRecentHistory` collector updates just `activities` and the hero footnote.
   - Always re-deriving in Flutter is harmless, but this is not Android behaviour.
   - The hero counts as "changed" only when `entityType` or `entityId` differs, regardless of action.
   - On a hero change the live path keeps the old footnote until the new one resolves. A failed `getAlbum` on an unchanged hero never wipes a good footnote.
3. **Cover fallback colour (item 11).** The `ExpressiveMediaArtwork` surface is `surfaceContainerHighest`, not `surfaceContainerHigh`. The type icon is 24dp in `onSurfaceVariant`, with `tonalElevation` 1dp on top. The Artist circle uses the same surface.
4. **Recently Added track-grid wording (item 9, "with <=? tracks").** The rule is:
   - `gridColumns = clamp(ceil(n / rows), 2, maxColumns)`.
   - The phone takes `maxColumns * rows = 4` tracks. One to four tracks use 2 columns. A short last row pads with a spacer weighted `columns - size`, so tiles keep their width.

**Missing, v1-relevant**

5. **Subsonic cover refs.**
   - Playlist `coverArt` is always `SourceRelative(playlistId)`, never null. Album `coverArt` is `coverArt ?: id`. A Track's own `coverArt` may be null, and tiles and cards then fall back to `albumId.rawId`.
   - The "artless playlists sort last" rule almost never fires on Subsonic, because `coverArtUrl` is always non-null. An empty playlist or a 404 cover must render as the type icon, not an error.
   - Android retries failed covers on network-back, app foreground, and a 3 s, 15 s, 60 s backoff (`ArtworkRetry`). Flutter should cap those retries and treat a 404 as final.
   - The icon stays under a failed cover. A cover URL that arrives late reveals over the icon with the crossfade.
6. **Pool rows and activity tracks are slim, and Home plays them.**
   - `home_grid_pool_cache` stores only id, title, artist, coverArt storage key, albumId, durationSec, and (albums only) version. It also stores subtitle, `sortOrder`, and `cachedAt`.
   - `ActivityEvent.asSong()` builds the same kind of slim Track: no album name, artistId, audioFormat, replayGain or trackNumber.
   - The playback and Now Playing specs must tolerate Tracks from Home, with no album name and no artistId. Android does not enrich them.
   - Recently Added tracks and freshly rotated pool tracks are full `getStarred2` / `getRandomSongs` tracks.
7. **Edit Home footer.** Android always appends an "Edit Home" `TextButton` after the last section (`homeEditFooterEntry`, `home_edit_footer`). Omit it in v1, because edit mode is deferred and a dead button would be worse. The bottom list padding and the 18dp item spacing already clear the bar. There is also an "all sections hidden" card (`homeAllHiddenItem`) that is irrelevant while the layout is read-only.
8. **Pointer devices (MateBook / desktop acceptance).**
   - `elasticPress` also scales to 1.01 (`HoverLiftScale`) while a mouse, trackpad or stylus hovers. Press wins over hover, and both run on the Standard spatial spring (0.9, 700).
   - The inner cover in `WidgetBackdropArtwork` is wrapped in `elasticPress` too, so a pressed card's cover scales about 0.97 × 0.97.
   - Cards use `clickable(indication = null)`, so no ripple.
9. **Activity row identity.**
   - `stableId` embeds the Room row `id`, so a new activity row for the same entity re-keys its card and resets that card's state.
   - Flutter's `ActivityEvent` needs a monotonically increasing id. A timestamp plus counter is fine.
   - `collapseToLatestUnique` keys on `actionType:entityType:entityId:provider`, and `homeActivityDedupKey` then dedupes on `entityType:id` (SONG uses `songId`), as the spec says.
10. **Staged-reveal latch.** The latch is `rememberSaveable(key)`, so it survives config change and covered-shell pauses. In Flutter, a process-wide static (spec item 14) is the right equivalent. A full process restart replays it, as on Android.
11. **No tab-reselect scroll-to-top.** Android has no "tap the Home tab to scroll to top" behaviour, so don't add one.
12. **Freshness after in-app stars.** Starring a track in Now Playing does not update Recently Added until the next Home load (no resume or timer refresh). State this in the QA notes so it isn't reported as a bug.

**Confirmed, no change needed**

- Greeting hour boundaries (5, 11, 13, 18).
- The Activities hero shows no type label.
- Cover sizes: JBI 480, everything else 320.
- Recently Added carries no edge fade. Recently Played, Your Playlists and Other Profiles use the 24dp scroll-aware fade.
- Tide geometry: front wavelength 72dp with a 36dp harmonic, back wave 116dp, `topInset = statusBar + 2dp`.
- The seam text line uses `tideTextSeamPx` only when the viewport owns the tide. Home uses `SeamTop.FadeText`, so it doesn't apply.
- Subsonic `addedAt` is the `starred` timestamp, and `libraryAddedAt` is `created`.
