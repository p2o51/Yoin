# v1 port spec: Now Playing: bottom-bar pill, ShellOverlayDown player (phone column, Expanded lyrics stage), queue sheet, cover-colour theming, playback-state reading and the system playback chain (Subsonic v1, phone/Compact)

> Generated 2026-11-13 by reading the Android app (read-only agents). Android refs are relative to app/src/main/java/com/gpo/yoin. The "Corrections" section at the end overrides anything above it.

## Overview

WHAT THE USER SEES, IN ORDER (phone, Subsonic only).
1) Idle: the bar is two labelled halves [Home][Library] (already ported). The moment a track exists the halves spring apart into the NAV POSE [Home 72|48][now-playing pill fills][Library 48|72]; the pill shows a 34dp cover, a marquee title over a marquee artist, and a primary@25% wash that fills from the left up to the playback fraction, its right edge a travelling sine wave (amplitude springs 0<->4dp with play/pause).
2) Tap the pill: the bar slides down+fades, the Now Playing overlay (ShellOverlayDown) rises from the bottom on a spring under a 50% black scrim, while the pill's cover (and title/artist as scaled text) fly into the player's cover/hero. ONE controller owns the overlay offset: the chevron, system back and the vertical drag-down all feed it; release past ~90dp (or a fast fling) commits, else it springs back. The chevron rotates 180 deg with the drag fraction.
3) The player is ONE column on a height budget (NowPlayingBudget): top bar (chevron + 'PLAYING FROM ...' label) / cover with a 56dp rating column beside it (vertical rating slider 0.0-10.0 + heart) / lyric window (>=2 clean lines, active line anchored at 22%) / transport (row 1: PLAY|PAUSE pill + NEXT on the left, play-mode circle on the right; row 2: PREVIOUS + elapsed + wave scrubber + -remaining) / hero (artist over a 36sp marquee title that breathes +-3% with play state) / pill row (Queue). Tapping the lyric window reshapes the stage in place (stageSettle spring 0.85/700) into the EXPANDED lyrics stage: cover flies to a 44dp docked thumb in the top bar, the full synced lyric list appears (tap a line to seek), transport and rating retreat, the hero stays. Back/chevron steps Expanded->Compact->closed.
4) The whole app (pill, Home, Library, NP) is themed by the playing cover: Palette seed -> SPEC_2025 Expressive scheme, applied in ONE cut (no colour tween; 51 chose this on 2026-11-04 and AGENTS' 'colours animate' is outranked by the code). NP's own background is a reactive 'room': at rest still, cover-colour wash crossfades over 820ms on song change, play/pause rings a bloom.
5) Queue pill opens a Standard-role modal sheet: Now playing / Next in queue / Next from <album>, tap to skip.
6) System chain: AVSession/continuous task (already in the engine) owns the real queue; Dart mirrors it. Lock-screen/headset/notification commands arrive as EngineState changes and the pill/NP follow with no special path; Subsonic now-playing + scrobble are reported by a Dart tracker using the Last.fm rule (>30s songs, half or 4 min of LISTENED time).
Everything below is Compact. Android refs are relative to app/src/main/java/com/gpo/yoin.

### 2. Now-playing pill content: cover, marquee title/artist, progress wave wash, track-change push

The pill fills its slot (height 48, shape 28 => stadium), clipped. Container = lerp(surfaceContainerHighest -> primaryContainer, trackPresence) and content colour lerp(onSurfaceVariant -> onPrimaryContainer), trackPresence 0/1 by (title != null) on the default effects spring; disabled looks identical. Inside: Row, horizontal padding 10, no vertical padding: [cover 34x34, 4dp corner (plain RoundedRectangle, NOT continuous: 'ThumbAnimated'), tonal elevation 1, fallback glyph MusicNote on surfaceContainerHighest, decoded at a fixed 96dp request size so the memory cache hits for twins][10dp][Column weight 1: title labelLarge (14/20 w500) color=content, maxLines 1, no wrap, Clip + marquee when a real title (initialDelay 1500ms, repeatDelay 2000ms, infinite, Compose basicMarquee defaults: 30dp/s, gap = one third of the container), artist labelSmall (11/16) color=content@72% with its own marquee (initialDelay 2500ms, repeatDelay 2000ms)]. Idle/error texts: title = connectionError!=null ? 'Playback unavailable' : 'Nothing playing' (Ellipsis not marquee); artist = the error message when there is no artist. WASH: drawn only if title != null && progress > 0, in its own RepaintBoundary: path = rect from x=0 to progressX (=width*front) whose right edge is a 20-segment sine: for i in 0..20, y = i/20*height, x = progressX + sin(phase + i/20*2*pi) * (4dp * amplitude); fill primary@25% (alpha 0.25). phase = 2*pi*(t mod 3s)/3s from ONE app-wide clock shared by every renderer (pill, any future second window); amplitude is a spring 0<->1 on play state (the first value is set without animation). While steady playing, step phase at ~25ms (30Hz) instead of every vsync (saves frames); the amplitude spring runs per vsync while it moves; stop ticking when paused and settled. FRONT SMOOTHING (PlaybackProgressSmoother): between position samples draw front = anchor + (now - anchorTime)/duration, clamped to anchor + 600ms-of-song lead; a new sample slightly BEHIND the drawn front (<=600ms) re-anchors at the drawn front instead of stepping back, a real seek/track change/larger gap snaps to the sample; paused or duration<=0 draws the raw progress. TRACK-CHANGE PUSH: the pill renders a held copy 'shown' of (id,title,artist,cover). When id changes between two non-null ids: (a) if mid-push, snap to 0; (b) animate p 0->1 over 90ms LINEAR (old content translateX = -30dp*p, alpha = 1-0.9|p|); (c) swap shown; snap p=-1; spring p->0 on Expressive default spatial (0.8, 380) (new content rides in from the right). Same id (metadata/cover refresh) or idle<->first track: swap silently (the idle->pill width morph is the entrance). The WASH is not part of the pushed row (it stays put). Tap: haptic contextClick then openNowPlaying; semantics: button, label 'Open player'.

**Motion:** push-out 90ms linear; push-in Expressive default spatial (0.8,380); trackPresence + colours default effects (1,1600); amplitude spring = Standard default spatial (0.9,700) (the pill lives under the bar's Standard role); wave period 3000ms; wave step 25ms when steady; marquee delays as above.

### 3. Overlay controller (ShellOverlayDown): open, collapse, drag, back, chevron share ONE controller; bar hides, scrim, corner clip

Class 'ShellOverlayDown' per AGENTS (Now Playing is a shell-owned overlay, never a route). One NowPlayingOverlayController in the shell holds: expanded (bool), dragDy (logical px >= 0, fed only by the vertical drag), and stage (Compact|Expanded). Every dismiss input (chevron tap, system back/back key/side-swipe, drag release, fling) calls controller.close(), which converts the current dragDy into slide progress and springs it out (no second displacement state: Android keeps dismissDragPx + predictiveBackProgress + the AnimatedVisibility slide; in Flutter fold them into one value y = (1-open)*H + dragDy and on commit set open = 1 - dragDy/H, dragDy = 0, seed the spring with the fling velocity). DRAG: vertical drag recognizer on the whole player root; only positive deltas count, and once started dragDy may come back to 0 (delta<0 allowed while dragDy>0). DISABLED while stage == Expanded (the lyric list scrolls) . Children that own vertical drags must win the arena on pointer-down: the rating slider claims on DOWN (eager/RawGestureDetector) and consumes every move; the Compact lyric window is tap-only (a tap that does not consume drags). RELEASE: commit when dragDy > 240 Android-px (~91dp @2.625x; use 90dp) OR velocity > 800 px/s (~300dp/s); else spring dragDy->0 on Standard default spatial (0.9,700). dismissFraction = clamp(dragDy/90dp,0,1) (read in draw) rotates the chevron by 180deg*dismissFraction. HarmonyOS back has no progress: system back = commit via close() (Android's three-button path); NO PopScope in feature code: add a shared back-infrastructure hook (write it into the predictive-back skill first, as README says). Back layering (level order, mutually exclusive): Expanded stage -> stepBackStage() (to Compact) ; Compact -> close(). Show/hide: the overlay is opaque (aurora paints `background`), enter = slide up from H on Expressive default spatial (0.8,380) + fade-in on Standard default effects; exit = slide down on Standard default spatial (0.9,700) + fade-out Standard effects (fade 'rides' the slide, it is not a cross-fade to the content below). Scrim = black, target alpha 0.5 while expanded, default effects (Standard). While the player is moving (enter/exit in flight or dragDy>0.5px) clip it to a rounded rect of the SCREEN corner radius (device corners; fallback 28dp; at rest clip nothing). The BAR: when expanded it leaves (fade-out + translateY by barHeight+navInset on Standard springs) and returns the same way on close; the bar is not composed during the open stage so its wave stops ticking. The player is NOT disposed on close until the exit finishes (reset stage to Compact only then; a re-open during the exit takes the pose back on the dragReset spring). Open entry points: pill tap; (later) notification/lock screen deep link should set expanded=true without morph. NP stays expanded across a pushed detail route (title/artist route taps are deferred, but the overlay must not be torn down by Navigator pushes).

**Motion:** enter: slideInVertically Expressive default spatial (0.8,380) + fadeIn Standard default effects (1,1600); exit: slideOut Standard default spatial (0.9,700) + fadeOut Standard effects; scrim Standard default effects; drag cancel Standard default spatial (0.9,700); commit continues from the dragged pose with the fling velocity (velocity-continuous retarget, SpringValue already does this). Honour MediaQuery.disableAnimations: fade only, no travel.

## Corrections (from a second reader — these win)
Audit of the Now Playing spec against the Android code. Most numbers, strings and spring values check out; the corrections and additions below are the exceptions.

WRONG (fix before implementing)

1. End of queue with repeat off.
   - Spec says: the engine goes idle, the pill returns to the idle pose, and NP closes.
   - Android does none of that. Media3 goes to STATE_ENDED and the last track stays in PlaybackState. The pill keeps its nav pose with that track, and NP stays open and paused.
   - `playWhenReadyOf` (player/PlaybackState.kt L101-110) is false for IDLE, ENDED and suppressed playback, so the button shows PLAY. Tapping PLAY calls `player.play()`, which restarts the queue.
   - NEXT on the last item is a no-op: `PlaybackManager.skipNext` only seeks `if (hasNextMediaItem())`.
   - Only an explicit clearQueue (the queue editor, deferred) empties the state and sends the pill back to idle.
   - Harmony should therefore keep the track on ended, drive `playWhenReady` off `phase` (false when idle or ended), and restart on PLAY. NP's Idle state is only for an explicitly emptied queue.

2. Error snackbar for Subsonic playback errors.
   - This is invented. Android's snackbar events (`PlaybackEvent.SpotifyConnectError`) are Spotify-only (`maybeEmitConnectFailure`, `PlaybackManager.kt` L1360-1375).
   - A Media3 error only sets `connectionPhase=Error` and `connectionErrorMessage=player.playerError.message` (L1130-1133).
   - The pill shows that message only when there is no title. With a track, nothing extra appears.
   - A snackbar is optional polish, not parity.

3. Cover reveal timing.
   - The spec says the artworkDissolve spring (damping 1.0, stiffness 45) gives a "~250ms perceived" fade. That is wrong. A critically damped spring at k=45 has ω≈6.7 rad/s, so it reaches about 90% at roughly 0.6s and settles (threshold 0.005) at roughly 1.1s.
   - NP's cover uses `ArtworkReveal.DotDissolve` (`NowPlayingScreen.kt` L6149), which runs on that slow spring.
   - Every other cover (pill, queue, Home, Library) uses `ArtworkReveal.Crossfade`, which runs on the default effects spring (1, 1600). It also snaps to 1 when the image comes from the memory cache (`ArtworkSwap.kt` L55, L83, L134). Pill and queue covers must therefore not use the slow spring.
   - For v1, NP's cover crossfade should be somewhat slower than the pill's. Do not assume it is fast.
   - Use the memory-cache snap everywhere.

4. Play mode is not persisted on Android.
   - Android keeps `preferredPlayMode` in memory only (`PlaybackManager.kt` L126, L841), defaulting to RepeatAll. It is re-applied to every newly started queue (`applyPlayMode` after `setMediaItems`, L586-612).
   - The spec's "KeyValueStore: play-mode last used" is a deviation. Either follow Android (a session-level field applied on each `setQueue`) or call the persistence a deliberate Harmony improvement.
   - With shuffle on, a fresh queue starts at the tapped item (Media3 semantics), not at a random track. The ArkTS engine must keep the start index first in its shuffle order.

5. Hero artist stretch, reduced-motion values.
   - The spec gives 1.02/1.01/0.99 for the artist. The title uses 1.02/1.01/0.99 (pressed/playing/paused) in reduced motion.
   - The artist uses 1.015/1.008/0.992 (`NowPlayingScreen.kt` L1358-1374). Normal-motion values (1.04/1.02/0.98 artist, 1.05/1.03/0.97 title) are as in the spec.

MISSED (v1-relevant)

6. LyricCreditsExtractor is missing from the lyrics pipeline.
   - Source: `data/lyrics/LyricCreditsExtractor.kt`, called from `SubsonicMappers.kt` `SubsonicLyricsList.toLyrics()` L198-216.
   - Chinese LRCs from NetEase/QQ carry credit lines at the head and tail ("作词 : …", "作曲 : …", "Bass Guitar：…", copyright notices, and QQ's first line "Title - Artist"). The owner's library comes from music-dl, so this will hit constantly.
   - Android strips them out of the lyric lines before they reach the window or the full list. They are kept separately in `Lyrics.credits`, which feeds the About tab; About is deferred, so drop them.
   - The rule, which Harmony should port as a pure Dart function with tests:
     - Scan only the head block and the tail block. Each scan stops at the first non-credit line.
     - A credit line is "role : names" (also "role - names" in English) with a known CJK or English role word. "Chorus:", "Rap:" and singer markers are not roles.
     - A parenthesised line counts as a continuation only directly under a credit line.
     - A block counts only if it has a headline role (作词/作曲/编曲/制作人), or three or more roles, or (tail only) the head block counted.
     - If fewer than two lines would remain, take nothing.
     - Run it for both synced and unsynced lyrics. Unsynced works on non-blank lines.
   - Without it, the spec's "intro before the first timed line" and the headerline logic misbehave, because credit lines carry timestamps around 0:00.
   - Also from `toLyrics()`:
     - Only `structuredLyrics.first()` is used.
     - Synced means `synced && any line has start`.
     - Synced lines are sorted ascending by startMs.
     - A null start becomes 0.
     - Unsynced text is the lines joined with newline.
   - Subsonic lyrics come from OpenSubsonic `getLyricsBySongId` only, with no legacy `getLyrics` fallback. Navidrome supports this endpoint.

7. Skip-direction constants.
   - The hold after the song lands is SKIP_DIRECTION_HOLD_MS = 1000ms (`NowPlayingViewModel.kt` L94), not "~1.2s". The tap-validity window is TransportTapValidityMs = 3000ms (`TransportPulse.kt` L174), as in the spec.

8. Play-mode button, second route to Off.
   - Besides long-press, four quick taps (each within 1500ms, `PlayModeCycleGapMs`) that go all the way round the 4-mode cycle also split the button (`ui/nowplaying/PlayModeCycle.kt`).
   - The deferral still holds, but the spec's "long-press is the only way to reach repeat-OFF" is inaccurate.
   - Tap transitions confirmed: RepeatAll→Shuffle→ShuffleRepeatOne→RepeatOne→RepeatAll, RepeatOff→RepeatAll, ShuffleRepeatOff→Shuffle.
   - `nextRepeat` (split pill) is all→one→off→all with shuffle kept.
