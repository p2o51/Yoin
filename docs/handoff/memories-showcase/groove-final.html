唱片刻纹，定稿

你选了唱片刻纹。这一版按你的意见改了三处：光跟着手机的倾斜走；获得动画按分数分成四档，一档比一档隆重；每一档都配了触感，节拍落在动画的关键帧上。掐丝徽记不再做徽记，它的线条拿去做了单色图标，见下一节。

定了什么 Memory 的徽记就是唱片刻纹：手机上 96dp 贴在封面右下角，短屏 72、平板 120、首页 44、日记顶栏 40。外形、三态（专辑分 / 曲目均分 / 未评）和配色规则都不变。
改了什么 光泽改由倾斜驱动。获得动画分四档：6 分以下、6–8、8–10、10 分。每档一份触感计划，用 Android 的 Composition 原语，手机不支持时退回 Yoin 现有的 YoinHaptics。
网页里看不到的 触感只有真机能感觉到。这里画出每一拍的时间轴；手机浏览器支持振动时会用 navigator.vibrate 粗略地震一下，但没有强度。

没有加载唱片刻纹组件（emblems/groove.js），这一节无法显示。

光跟着倾斜走

光固定在屏幕坐标里，像一盏顶灯照着唱片。手机往哪边倾，光就往反方向滑：评过分的刻纹上那道蝴蝶结形的反光跟着转（最多约 ±32°），亮度在 0.6 到 1.0 之间变，光心最多偏 3.5%。专辑分的曲奇标签上还有一道斜向细光，跟着同一个倾斜滑动；曲目均分没有这道细光。未评的盘没有刻纹可亮，只有一层很淡的无色反光，所以它也会动，但不会变彩。

拖左边的圆盘倾斜；鼠标在下面的标本上移动也会带动光。所有标本共用同一个倾斜源。

Compose 怎么做。用 SensorManager 注册 TYPE_GAME_ROTATION_VECTOR（陀螺仪和加速度计融合，不用磁力计，不受附近金属干扰，也不会慢慢转向北），采样率 SENSOR_DELAY_GAME。只在 Memory 卡真正可见时注册：Memories 已展开、这张卡是 pager 的当前页、Activity 处于 RESUMED，任何一条不满足就立刻注销。每个样本走 getRotationMatrixFromVector，按屏幕方向 remapCoordinateSystem，再 getOrientation 取俯仰和横滚。减去一条 τ = 1.6 s 的低通基线，握持姿势会自动归零，只留下“比刚才多倾了多少”；±18° 映射到 ±1，再限幅到单位圆。结果写进一个 Animatable，用 spring(dampingRatio = 0.9f, stiffness = 90f) 跟随，顺便滤掉手抖。光泽层画在 drawWithCache 里，只在 onDrawWithContent 读这个 State 再 rotate，所以倾斜只触发重绘，不触发重组。系统关闭动画，或 LocalMotionProfile 为 AdaptiveReduced（省电模式、低内存设备）时不注册传感器，光固定在 −128°。耗电很小：融合在传感器 hub 里完成，注册时长只覆盖用户看卡的那几十秒，不持有 wake lock，熄屏或切到后台都会注销。翻页时光不再跟页偏移走，倾斜是光的唯一输入，免得两套位移叠在一起。

  • 静止光角 −128°（左上方）
  • 倾斜映射 相对基线 ±18° → ±1，限幅单位圆
  • 基线低通 τ = 1.6 s
  • 跟随弹簧 dampingRatio 0.9 · stiffness 90
  • 光角偏转 最多约 ±32°
  • 亮度 0.6 – 1.0，静止 0.8
  • 光心偏移 尺寸的 3.5%
  • 曲奇细光 只给专辑分，偏移 0.55 × 标签半径
获得动画分四档

四个样例是同一张专辑（m1 的配色，10 首里评了前 5 首），只改分数，所以差别只来自档位。每升一档多一个动作、多几拍触感；最长的 10 分也不超过 1.6 秒。所有运动都来自弹簧，闪光的淡出是指数衰减，不用线性补间。未评没有获得动画。减弱动效时直接显示终态，触感只保留这一档最重的那一拍。

    档位时刻画面上发生的事Composition 原语 × 强度不支持时（YoinHaptics）

    节拍从哪来。每一拍都是在动画用的同一条弹簧曲线上找出来的：落定那一帧、盘面回到 12 点、回摆的顶点、标签压到最低、每一圈亮到最亮、外圈闪到最亮。改弹簧常数，节拍跟着变，不用手对时间。两拍间隔小于 45 ms 会糊成一下，只留强的那一拍。

    和评分提交的关系。提交评分本身已经有一下 click。获得动画在提交后 120 ms 开始，第一拍不会和它粘在一起。振动用 USAGE_TOUCH，用户在系统里关掉触摸振动时自动静音。

    回退。Composition 原语要 API 30（LOW_TICK、THUD、SPIN 要 31），而且要先问 areAllPrimitivesSupported。不支持时按同样的时刻调用 YoinHaptics；没有对应常量的拍（QUICK_RISE）直接跳过，满分的逐圈 tick 只留第一下，因为 View 级触感连发会糊成一片。

    // beats：和动画同一组弹簧常数算出来的 (atMs, id, scale)
val ids = beats.map { it.id }.toIntArray()
val v = vibrator
if (SDK_INT >= 31 && v.areAllPrimitivesSupported(*ids)) {
    val dur = v.getPrimitiveDurations(*ids)
    val c = VibrationEffect.startComposition()
    var cursor = 0
    beats.forEachIndexed { i, b ->
        // delay 从上一拍结束算起
        val wait = (b.atMs - cursor).coerceAtLeast(0)
        c.addPrimitive(b.id, b.scale, wait)
        cursor = maxOf(cursor, b.atMs) + dur[i]
    }
    // 和动画同一帧启动；USAGE_TOUCH
    v.vibrate(c.compose(), touchAttrs)
} else beats.forEach { b ->
    scope.launch {
        delay(b.atMs.toLong())
        b.fallback?.invoke(haptics)
    }
}
    在展示柜里

    上面的展示柜原型（“在真实流程里换徽记”）现在默认就是唱片刻纹，其他徽记仍可切换。“播放获得动画”按当前这张卡的分数走对应档位，同时在按钮下面画出这一次的触感时间轴；鼠标移到手机上，光也会跟着动。四张样例卡分别落在下面这几档，点“播放”可以在这里直接看。

    光为什么往反方向走

    顶灯不动，唱片朝右倾，灯在唱片上的倒影就往左滑。照这个物理关系做，手感才像真东西；反过来做会像光“粘”在手指上。

    分寸

    偏转封顶约 32°，亮度只在 0.6–1.0 之间。光要像一直在那里，而不是一个会跳的特效。静止时和原来那张定稿图完全一样。

    档位怎么定

    按显示出来的一位小数算：5.95 显示 6.0，就走第 2 档。专辑分和曲目均分用同一套档位，专辑分的标签压得更重一些（幅度 1 对 0.7）。

    没验证的

    真机上的震感强弱、各原语的实际时长（Pixel 和其他品牌差别很大）、传感器在平板横屏下的坐标换算，都需要上 Pixel Tablet 再调。
