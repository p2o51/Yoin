# Subsonic → DLNA / Sonos 验证记录

日期：2026-10-20。代码基线：`ee2737b7a`。工作分支：`codex/dlna-playlist-validation`。

## 范围

本次实现 Subsonic / OpenSubsonic 的直连音响播放，音响从服务器读取音频，Yoin 发送播放控制与元数据。复用正在播放的设备面板和 Media3 会话。

Apple Music 不接入这条 DLNA 路径。核对了 MusicKit Android 的 `MediaPlayerController` 和 `PlayerMediaItem` 公开接口：前者提供播放与队列控制，后者提供元数据，均没有可交给普通 UPnP renderer 的完整歌曲流地址或 DLNA 输出接口。这个结论针对 Yoin 的 MusicKit 集成，不代表 Sonos 原生 Apple Music 服务不可用。

## 官方依据

- [UPnP 设备与服务规格入口](https://openconnectivity.org/developer/specifications/upnp-resources/upnp/)：SSDP、设备描述与标准化 AV 服务。
- [AVTransport:3 规格](https://upnp.org/specs/av/UPnP-av-AVTransport-v3-Service.pdf)：URI 设置、播放、停止、跳转和状态读取。
- [MusicKit Android MediaPlayerController](https://developer.apple.com/musickit/android/com/apple/android/music/playback/controller/MediaPlayerController.html)：MusicKit 播放控制范围。
- [MusicKit Android PlayerMediaItem](https://developer.apple.com/musickit/android/com/apple/android/music/playback/model/PlayerMediaItem.html)：公开的媒体元数据。
- [Sonos Playback](https://docs.sonos.com/docs/playback-on-sonos)：音响自行请求音频 URI 并读取编码音频；Sonos 音乐服务集成与本次通用 UPnP 控制是不同接口。

## 真机播放与完整交接

用户确认先验证本地测试音源。独立安装 `com.gpo.yoin.dlnaqa`，不向日用 Yoin 添加测试账号。测试服务器实现 Subsonic API 和两首 30 秒 WAV，逐个请求验证 `u` / `t` / `s` 认证参数；未签名控制请求返回 401，正确签名返回 200。使用真实 `SubsonicMusicSource` 读取专辑、生成认证 stream URL，再走生产 `PlaybackManager` 和 `PlaybackService`，不是仅在电脑上发送一条 Play 指令。

| 场景 | 结果 |
| --- | --- |
| 平板本地开始播放 | 两首歌曲实际进入 Media3，第一首位置持续前进 |
| 从播放到约 14 秒的位置选择 Sonos Beam | 自动解析到同组主设备 Era 300；音响拉取认证音频并通过 Range 从目标进度继续，真实 PLAYING 状态通过 |
| 暂停与 seek | Sonos 返回 PAUSED_PLAYBACK；暂停中跳到 5 秒，后续多次观察固定在 5 秒；继续播放后位置前进 |
| 下一首 / 上一首 | 当前媒体 ID、索引、音响音频 URI 一同切换，状态符合命令 |
| Home + 熄屏约 100 秒 | 30 秒歌曲自然结束后，后台自动进入下一首；按 Yoin 既有 Repeat All 继续循环，多个边界连续接续 |
| 切回平板 | 音响实际确认 STOPPED 后才恢复本机，探针核对相同曲目、索引和进度，误差不超过 3 秒；两轮完整交接均通过 |
| 现有设备面板 | 发现两台音响；选择非主设备后正确把实际主设备标为当前；点 This device 可切回 |
| 面板系统返回 | 关闭设备面板，Now Playing 仍保留；复用既有 sheet 与返回控制 |

## 验证边界

本次验证的是受控 Subsonic 兼容 API、认证 URL、真实 Sonos 和 Yoin 的完整控制链；没有验证私人服务器的网络可达性、其完整格式集合或音质。WAV 之外格式与其他品牌 renderer 需要各自设备样本。Apple Music DLNA 按本次约定跳过；Spotify 继续使用现有 Connect。这个任务没有实现跨来源混合播放。
