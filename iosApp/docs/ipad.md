# iPad / 大屏

## 现在的样子

iPad 用 `PadShell`（`Yoin/Shell/PadShell.swift`），不用系统 Tab 栏，也不用侧边栏。两列都通到屏幕顶边（状态栏下面是和手机一样的柔和色带），导航交给 Yoin 自己的两块浮动玻璃，放在窗口底部的两个角：左下是导航胶囊（Home、Library、Search），右下是手机上那颗迷你播放器（51 2026-11-11 定：不要系统 Tab 栏和侧边栏；「两个角」胜过「底部居中一条」）。宽窗口里详情页在同一窗口的右列打开，Now Playing 是列旁边的侧栏，放不下时直接 Full。

早先这一页比较过三个方案（A 系统顶栏 + Inspector、B 保留 Yoin 底栏、C 三栏侧边栏）。最后做的是 B 的变体（两个角），A 和它的 Labs 开关、`-ipadNav` 参数都已删掉（e29bb8768）。

## 守住的 Android 原则

1. **按容器的宽高换档，不按设备型号。** 进不进 `PadShell` 看系统的 `horizontalSizeClass`（regular 用 `PadShell`，compact 用 `PhoneShell`，所以 iPad 上很窄的窗口就是手机界面）；进了 `PadShell` 以后，列、侧栏、Full 的档位都读窗口的实际宽高，照搬 Android 的 840 / 480 和 744 这几条线（侧栏旁的单列是 360，不是 Android 的 320，见下面 Panel）。
2. **一套 Now Playing 状态链：Closed → Panel → Full。** 从侧栏进 Full，关掉 Full 回到侧栏（不论是 ⌄、下拉还是返回）；从迷你播放器进 Full，关掉回到迷你播放器。
3. **详情是同一窗口里的列，不是第二个窗口。**
4. **换档不落在弹簧中途；数量跟宽度走，卡片内部不缩放。**
5. **返回是进入的反序（Android #200）。** ⌘[ 先关盖住整个窗口的（搜索、Full Now Playing、窄窗里推上来的页），再按打开顺序从新到旧关并排的面：Now Playing 侧栏、详情列（先退列里的栈，再关列）、Memories。列里再开一页、侧栏进歌词或专注、侧栏放大成 Full，都算重新进入，记为最新。规则在 `Shell/ShellBackOrder.swift`（纯函数，有单测）。

## 导航

- `TabView` 只有一个 Tab，Tab 栏隐藏（`.toolbarVisibility(.hidden, for: .tabBar)`）。Home / Library 和 Search 在这个 Tab 里交叉淡入淡出，各自在两次访问之间保留状态（Search 第一次打开时才建）。
- 导航胶囊和迷你播放器就是 `ShellBar` 的两半（`pad: .nav` / `pad: .player`），所以选中态、颜色、波浪、长按和失败横幅都和手机一样。尺寸在 `PadDockMetrics`：玻璃高 60，离底边 22、离侧边 24，播放器宽 320。
- NP 侧栏开着时迷你播放器让开（不然屏幕上有两个播放器）。Memories 从 Home 下拉时占满整个窗口，两块玻璃跟着下拉退场。
- **底部色带（iPad 第二轮 D1，51 2026-11-27 定）：** 每一列的底部有一条和顶部状态栏色带成对的柔和色带（`Shell/PadDockBand.swift`：薄磨砂加 surface 色，下面 45 % 实、往上缓到透明，高 = 离底 22 + 玻璃 60 + 44），导航胶囊、迷你播放器和详情列的「播放 ▾」都坐在这条安静的边上，列表在玻璃前淡出，不再从玻璃下面直接穿过。色带画在列里、「播放 ▾」下面（不盖住它）；Home 往下滚把浮动玻璃收起时色带一起淡出。「两个角」的布局不变（没做 D2 的合体栏）。

## 两栏 Home（parity p4 B2，2026-11-26）

- **换档线是 Home 容器的宽高，不是方向：** 容器 ≥ 840 宽且 ≥ 480 高就排两栏（`HomeDensity.wide`，走 :shared 的 `homeTwoColumn`，和 Android、鸿蒙同一条线）。13" 竖屏（1032）是两栏，11" 竖屏（834）是一栏；右边开了详情列、把 Home 挤到 840 以下时退回一栏。iPhone 横屏高 < 480，永远一栏。
- **行：** 一行是一个整宽区块，或者两个半宽区块，中间 20（`HomeFeedRows.swift`，`HomeFeedRowsLayout`）。每个区块正好是整数个格高：40 + n·150 + (n − 1)·14，半宽一对共用一个格数（左边那个的，钳在两边范围的交集里）。每个格子按自己的宽度重新算密度（Android `forHomeColumn`）：半宽排半宽的卷数和列数。区块按 id 排成一个平铺列表，所以配对、拆开、拖放、撤销时区块是移过去、缩放过去，不是淡出淡入。
- **各区块在格子里的排法（照 Android）：** 动态 = 手机的便当，行数按格数（1 S、2 M、3 XL）；接着听 = 每格一行封面（106 方 + 两行字），能放几列放几列，记忆卡占两列；最近添加 = 每格三行歌曲（⌊宽/280⌋ 列），后面是每格一张的专辑；封面书架（最近播放、你的歌单、为你推荐、其他账号）= 一到两行、每张一格高；重温 = 每张一格高，半宽一页两张；歌词卡片 = 整页整张（半宽一页一张、整宽一页两张），高度是格子内容高（只有 Beta 开启提示时提示占一格、这一行也只有一格高，旁边的半宽区块下面不再空一块：`HomeGrid.shownUnits`，iPad 第二轮，51 2026-11-27 定；按钮在标题行右边，正文最多 5 行）；全部 Memories = 卡片填满标题下面的格子。
- **半宽的书架按页翻：** 每页整数张卡片，间距拉开让第一张和最后一张贴边；一次滑一页（400 pt/s 以上按方向翻，否则就近），标题行右边是页点和 ‹ ›（`HomeGridShelf`）。整宽的书架照旧自由滚动、出血到窗口边。
- **编辑：** 进编辑时，没改过的布局从大屏默认（`WideDefault`）开始；拖动走 :shared 的 `HomeDragCore`（两栏规则 ①–④：拖到整行区块中段的外侧 30 % 并排，上下四分之一自成一行，碰到别人的一对只能放上下）；宽度跨过 840 时草稿跟着走（没动过就是新宽度的默认，动过就保留顺序、两栏从记忆里重新配对），拖到一半宽度变了就回滚。重置回到这个宽度的默认；两种默认写进去都等于「从没改过」（`isAnyDefault`）。
- **⌟ 手柄：** 两栏时每个区块都有，先往哪个方向拖就锁哪个轴。横拖改宽窄：整行往左拖过中点变成左半、把下一行拉上来并排；半宽往外拖过中点变回整行。手指按着时宽度 1:1 跟手（比半宽再窄一点有橡皮筋），虚线框显示松手会吸附到的宽度。竖拖改格数：在这一对的交集范围里 1:1 跟手（两端各 24 的橡皮筋），每过一个格数一下震动，松手吸到最近的格数。聚焦手柄时 ←/→ 改宽窄、↑/↓ 改格数（iPad 键盘、Mac）。
- **VoiceOver：** 区块的值多一句「左半边 / 右半边」；动作多了「放到上一个旁边」「改为整行」，两栏的「更多行 / 更少行」改格数。手柄的值是「半宽 / 全宽」，动作「半宽 / 全宽」，调节改格数。
- **指针：** 编辑时指针移到拖动手柄和 ⌟ 上变成四向移动光标（`HomeHandlePointer`，一栏时拖动手柄只有上下箭头）。右键仍然是卡片的上下文菜单（`SecondaryClick.swift`），不进编辑；进编辑用按住（点按住也一样）、页脚的「编辑首页」或账号卡片。触控板双指捏合由 `UIPinchGestureRecognizer` 交给列表模式。Mac 上 iPad app 拿不到 UIKit 的指针样式，所以移动光标只在 iPad 上有。
- **编辑时收起底部：** 不论一栏两栏，编辑模式下浮动导航胶囊和迷你播放器（手机上是底栏）随编辑进度 P 退场（Android 编辑时也只留撤销 / 完成），退出时原路回来。
- **11" 旋转：** 窗口宽度跨过 840 时 iPad 的 shell 会重建 Home 的视图树（单栈 ↔ 分列），编辑会话放在 `AppModel.homeEditor` 里，不跟着视图丢，所以竖屏一栏进编辑、转到横屏是两栏的同一份草稿。
- **Tip（parity p4 B3）：** 「重新排版首页」照 Android 2026-11-23 版：iPad 和 Mac 上是平板演示（`DemoPhone` 的 `wide`：16:10 横放平板、880 宽的屏、左下角的导航胶囊；进编辑、捏合收成列表再放开、长按拖动、拖到旁边并排），文案是 Android 的原话；iPhone 永远一栏，演示没有「拖到旁边」这一步，文案去掉「大屏上拖到旁边即可并排」（`Tip.oneColumnText`，`Tips.available(_:keyboard:twoColumn:)`）。
- **还没做：** 列表模式（捏合后的条带）在两栏里仍是一栏条带，不显示半宽条带；半宽书架翻页时边缘的潮线遮罩；全部 Memories 在格子里的「Memories 墙 + 评分专辑」排法（现在是把手机卡片放进格子）。

## 详情列

- 窗口宽 ≥ 840 时，专辑、歌手、歌单、Settings 都在右列打开；更深的页面在列自己的 `NavigationStack` 里推入，shell 列不动。窗口窄于 840 时只有一个栈，所有页面推到 shell 上面。窗口跨过 840（11" 旋转、分屏、台前调度）时，右列里的专辑跟着走：变窄时推到单栈最前面（列里在它上面推的页留在上面），变宽时回到列的根；在单栈里退掉它，列也就忘了它（`AppModel.padPath`）。两栏 Settings 盖住整个窗口时，左下导航胶囊和右下迷你播放器向下退出窗口，关掉 Settings 再回来。
- 列宽照搬 `resolvePaneBudget`：shell 份额 0.45，窗口 ≥ 1080 时 shell ≥ 600，两列都 ≥ 360。中间是自己画的把手（`DragGesture` 1:1 跟手、钳制、不吸附，松手停在原地；窗口宽度一变就回到预算值）。不用 `NavigationSplitView`。
- 开列时 shell 在点击那一帧让出列宽，列带着页面从右边滑进来；关列时列先滑出去，shell 在落定时收回宽度。都是 spatial 弹簧。
- 详情列和推入的详情页各有一个 Play 分裂按钮，在列的左下角；列太窄放不下 Play 和迷你播放器同一行时，Play 抬到上面一行。

## Now Playing

- **Panel：** 自己画的侧栏（不是系统 `.inspector`，因为它在窄窗口会自己变成底部弹层）。通到窗口的上、下、右边（不再是离边 8、圆角 28 的卡片），背景是和 Full 一样的磨砂玻璃加前后专辑的颜色，和列之间只有一条细线（2026-11-27 iPad 审查：原来的卡片和平涂渐变「像贴上去的」）。宽 = clamp(窗口宽 × 0.5, 360, 420)。只有当窗口减去侧栏还剩 ≥ 360（开着详情列时 ≥ 744）才开侧栏，否则点迷你播放器直接进 Full（`AppModel.padPanelFits`，`PadPanelFitTests`）。360 是分栏两列自己的下限；Android 用 320，但 13" 分屏 1/2（683）旁边只剩 315 时，Home 的卡片文字一字一行（2026-11-27 iPad 审查），所以 iPad mini 竖屏（剩 372）有侧栏、13" 分屏 1/2 直接 Full。侧栏开着时如果又开了详情列、两列放不下，侧栏退开；窗口变窄（转竖屏、分屏、台前调度拖小）让侧栏放不下时，侧栏变成 Full（Android 的 frame 同样把 Panel 换成 Full），关掉 Full 在放得下时回到侧栏，不会出现三列挤在一起。进出按自己的宽度平移，不淡入淡出。
- **Full：** 从右下角的迷你播放器长出来、关闭时折回去（`NowPlayingMorph`，和手机同一个进度：⌄、拖动、返回都驱动它）；从侧栏进时从侧栏的位置长出来。窗口宽 ≥ 840、高 ≥ 480 **且宽 > 高**时是双栏播放器（`NowPlayingPadFrame.wide`），其他 iPad 窗口（竖屏，13" 竖屏 1032 也算）是放大的手机单栏（`.enlarged`）。
- **双栏 = 方案 A（iPad 第二轮，51 2026-11-27 定；`DualPaneBudget`）：** 内容最宽 1220、在窗口里居中，左右 44 : 56。左栏：封面按列宽和高度放大（最大 460，13" 横屏 458、11" 横屏 432），右边是 56 的评分条和心形；歌手 / 音质 / 两行歌名、进度和播放控制紧贴在封面下面，整块在高度里居中（以前左栏锁在 Android 的 312、歌名沉到窗口底，中间空约 500）。右栏：页签放在顶栏里、对齐右栏的字；歌词 28（翻译 18），行宽最多 600；底部只有这一页自己的工具（歌词键 / 问 AI / 写笔记）。矮窗按同一个梯子：两行歌名 → 一行 → 封面变小 → 歌名进顶栏。专注：评分条退场、封面最多 1.5 倍、右栏至少留 320。和 Android DualPane 不同（Android 还是 312 的左栏），记在 `docs/platforms.md`。
- **竖屏 = 方案 B2：** 高 > 宽的 iPad 窗口都走放大单栏（13" 竖屏、11" 竖屏、mini、竖着的分屏）：居中的海报列（宽 ≤ 584，`NowPlayingPadFrame.posterMaxWidth`：Android 的 640 让 13" 和 11" 竖屏的封面到了 523；现在每台竖着的 iPad 都是同一张海报，封面约 480 加约 93 的评分条，控件 60），封面下面是歌词预览、播放控制和歌名；点歌词 / 关于 / 笔记（展开）时封面收成顶栏里的小卡，这一页拿到整列宽。以前 13" 竖屏按宽度走双栏，内容挤在上面三分之一。
- **小窗口改成从按钮弹出（iPad 第二轮，51 2026-11-27 定；`Theme/AnchoredPopover.swift`）：** iPad 在 regular 宽度的窗口里，歌曲面板（`TrackMenuSheet`）、队列、Spotify 设备是 `.popover`，从打开它们的地方弹出：队列和设备从双栏顶栏的图标或单栏的胶囊弹出；歌曲面板从按下 / 点按的位置弹出（窗口上一个只记录按下位置、立刻失败的手势 `LastTouchRecognizer`，3 秒内有效，所以行的长按、卡片长按、迷你播放器长按、右键都一样）。账号卡片还是「从头像长出来」的动效，但停在头像下面（宽 380，右边缘对着头像），页面不再后退变暗。compact 宽度（Slide Over、窄分屏）和 iPhone 仍是原来的底部面板。右键仍然打开歌曲面板（不是系统的上下文菜单），只是在 iPad 上以 popover 出现在指针处。分享、歌词搜索 / 编辑、歌单恢复仍是 sheet。
- **双栏专注的点阵（I32，51 2026-11-13 定：只做 iPad 双栏，iPhone 保持无点阵）：** 点封面进专注时，评分列、页签和歌词工具碎成细点退场（`FocusRetreat` → `DotDissolve`；顶栏只淡出，因为里面的 AirPlay 选择器是 UIKit 视图，shader 画不了）；同时从封面那一侧向窗口四边炸出一圈整齐的点带（`NowPlayingEdgeBand.swift`，shader `yoinEdgeBand`，Android EdgeDotBand），约 0.2 s 最宽、1 s 内收细、2 s 起退、8 s 消失；专注里换歌再炸一次并从左扫过，每换一行歌词从歌词处推出一道涟漪，暂停时波变慢、带变细。Reduce Motion：只淡出，没有点带。

## iPad 专属的补充

- **键盘：** `Yoin/App/YoinCommands.swift`，和 YoinMac 的 Controls 菜单同一套快捷键，按住 ⌘ 能看到。
  - Controls：播放 / 暂停（空格）、下一首（⌘→）、上一首（⌘←）、快进 / 快退 5 秒（→ / ←）、随机（⌥⌘S）、循环（⌘R，按播放模式键的顺序 全部 → 单曲 → 关，菜单项写的是按下去会变成什么：列表循环 / 单曲循环 / 关闭循环）、喜欢（⌘D）、Now Playing（⇧⌘P，有空间时开侧栏）、专注封面（⌥⌘F）、歌词（⌘L）、队列（⌥⌘U，Mac 上 Apple Music「待播清单」的键；Now Playing 关着时先打开它，再从队列按钮弹出）、Search（⌘F）、返回（⌘[）、关闭（Esc）、Settings（⌘,）。
  - 2026-11-27（iPad 第二轮，51 定）：⌘F 从「专注封面」改成 Search（iPadOS / macOS 的查找习惯），专注封面换成 ⌥⌘F；⌘K 不再是搜索。写笔记、翻译歌词以后再加。Mac 上的 iPad app 用同一套。
  - Go：Home（⌘1）、Library（⌘2）、All Memories（⌘3）。
  - Esc：输入法正在选字时不动（让它取消候选）；输入框有键盘时只收起键盘；否则同 ⌘[（`KeyboardEscape`，`PadKeyboardTests`）。⌘3 只打开一次全部 Memories：已经在路径里就回到它，两栏设置和搜索先关掉。
- **指针：** 卡片在指针下抬起（`PressScale` 的 `.hoverEffect(.lift)`）；歌曲行、展开歌词行、底栏胶囊、分栏把手用 M3 悬停状态层（8 %，effects 弹簧），进度条未播部分加深 8 %；把手的指针是竖线加左右箭头（`Theme/PointerHover.swift`）。右键（或 Control 点按）打开和长按同一张歌曲面板（`Theme/SecondaryClick.swift`）；歌曲、专辑、歌单能拖到队列或歌单上（`Library/YoinDrag.swift`）。
- **单窗口：** `UIApplicationSupportsMultipleScenes` 关着（`project.yml`），iPad 和 Mac 上都只有一个窗口，「新建窗口」（⌘N）也去掉了（`YoinCommands` 的 `CommandGroup(replacing: .newItem)`）。原因：所有场景共用一个 `AppModel.shared`，第二个窗口只是第一个的镜像（页面路径、侧栏、Full 的状态全部共享），不是 Android 的「一个窗口一棵树」。要重新开多窗口，得先让每个场景有自己的导航状态。
- **窗口拖动缩放：** 列宽、侧栏是否放得下、Full 的档位都按实时宽高重新算；把手拖过的宽度在窗口宽度变化时作废。
