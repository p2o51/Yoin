Owner decision (51, 2026-11-05): iOS follows Android's **current** Subsonic stream-quality rule (origin/main 39ece83ca, `player/StreamQuality.kt`, `SubsonicStreamResolver.kt`), replacing iOS's "wired Original, else 128 kbps". Fix commit: 857be362b.

| ID | Verdict | Resolution | Fix commit |

| O01 | RESOLVED (owner chose Android) | The rule now lives in `:shared` (`com.gpo.yoin.shared.data.StreamQualityPolicy`, `StreamQuality`, `AudioOutputKind`, `StreamQualitySettings`, `StreamPlan`); iOS calls it. Android still uses its own copy (no migration); values match. | 857be362b |

## The rule

| Setting | Choices (Android labels) | Default |
|---|---|---|
| Wi‑Fi (unmetered) | Auto, Original, 320 kbps, 192 kbps, 128 kbps | Original |
| Mobile data (metered) | same | Auto |

Auto ("Wired Original   Bluetooth 320 kbps   Speaker 192 kbps"):

| Output kind | Android AudioDeviceInfo types | iOS AVAudioSession ports | Quality |
|---|---|---|---|
| Wired | wired headphones / headset, USB headset / device / accessory, line analog / digital, aux line, HDMI | headphones, usbAudio, lineOut, HDMI | Original |
| Bluetooth | A2DP, hearing aid, BLE headset / speaker / broadcast | bluetoothA2DP, bluetoothLE | 320 kbps |
| Speaker | everything else (built-in speaker, dock, SCO, bus, cast …) | everything else (builtInSpeaker, builtInReceiver, bluetoothHFP, airPlay, carAudio, unknown) | 192 kbps |

Several outputs: wired wins, then Bluetooth, else speaker. Network: unmetered = Android NET_CAPABILITY_NOT_METERED; iOS = NWPath satisfied and neither `isExpensive` nor `isConstrained` (Low Data Mode). No network = metered.

Plan (Android `StreamDelivery.plan`): no cap → the file; source bit rate known and ≤ cap → the file; else `maxBitRate=<cap>&format=mp3&estimateContentLength=true`. `timeOffset` only where the server lists OpenSubsonic `transcodeOffset` and the source rate is known (A38, unchanged).

Timing: chosen when a song opens (or is preloaded); a network change, a route change or a Settings change re-plans the preloaded next song and never restarts the current one.

Storage: per device, UserDefaults `streamQualityWifi` / `streamQualityMobile` with Android's keys (auto / original / 320 / 192 / 128). The old single `streamQuality` value migrates once: Automatic (or none) → the defaults, an explicit quality → both networks.

Tests: `:shared:allTests` 196 + 196 (`StreamQualityPolicyTest` 15, mirroring Android's `StreamQualityTest` policy cases). iOS: 197 run, 1 skipped, 0 failures (`StreamQualityTests` new: labels, port mapping, network mapping, defaults by network × route, shared plan, migration).
Simulator (iPhone 17 Pro, demo Subsonic :4991, `-silentAudio YES`, 320 kbps source): defaults on the Mac's network → `unmetered=true route=Speaker → original`, plain `stream.view?id=…`; with `-streamQualityWifi auto` → `output=Speaker → 192`, `maxBitRate=192&format=mp3&estimateContentLength=true` (current and preloaded). Logs carry no credentials.
